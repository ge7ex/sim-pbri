# Master Data Intake — พร้อมเพิ่มผ่านเว็บหลังสำรวจ

สถานะ 9 ตุลาคม 2569: ผู้ใช้ยังไม่มีข้อมูลสำรวจจริง ยังไม่มีการ import หรือเพิ่มข้อมูลจริงจาก checklist นี้ แบบฟอร์ม Admin ที่มีอยู่ผ่าน UAT ใน SQLite แยกแล้ว

## ลำดับกรอกข้อมูล

1. ตรวจวิทยาลัยและบัญชี Admin/Staff ของหน่วยงานให้ถูกต้องก่อนกรอก ระบบเป็นผู้กำหนด College จากผู้ใช้ ไม่มีช่องเลือก College ข้ามหน่วยงาน
2. **ทรัพยากร SIM** (`/app/resources`) → เพิ่มห้องและอุปกรณ์
3. **หุ่นจำลองและทรัพย์สิน** (`/app/simulators`) → เพิ่มประเภท แล้วเพิ่มทรัพย์สินจริง
4. **รายวิชาและสถานการณ์** (`/app/scenarios`) → เพิ่มรายวิชา แล้วเพิ่ม Scenario และชุดแนะนำ
5. ตรวจความพร้อม → ผู้ใช้จริงทดสอบคำขอจองภายใต้การยอมรับจากเจ้าของข้อมูล

## ช่องที่ต้องสำรวจและเตรียม

| กลุ่ม | บังคับตามเว็บ/validation | เพิ่มเติม/ข้อกำหนดเพื่อใช้งาน |
| --- | --- | --- |
| ห้อง | ชื่อ, kind=room, สถานะ, quantity=1, exclusive=true, capacity 1–10,000 | อาคาร ≤120 ตัวอักษร, ชั้น ≤64, ตำแหน่ง, รายละเอียด ≤2,000, ผู้รับผิดชอบเลือก Staff ใน College เดียวกัน; ภาพ JPEG/PNG/WebP ≤5MB และ ≤3000×3000 |
| อุปกรณ์ | ชื่อ, kind=equipment, ready/pending/maintenance, quantity 1–100,000, exclusive flag | ชื่อ ≤255, ตำแหน่ง/รายละเอียด; exclusive ขอครั้งละ 1, shared ขอได้ตาม inventory และเวลาว่าง |
| ประเภทหุ่น | ชื่อ, active flag | ชื่อไม่ซ้ำใน College; รายละเอียด; ปิดประเภทแล้วไม่ให้เลือกทรัพย์สินประเภทนี้สำหรับจองใหม่ |
| ทรัพย์สินหุ่น | ประเภทใน College, ชื่อ, active/disabled/maintenance | รหัส ≤64 ไม่ซ้ำใน Collegeถ้ามี; ตำแหน่ง, รายละเอียด; ข้อมูลการเงินกรอกทั้งปีซื้อ ค.ศ. 1900–ปีปัจจุบัน/ราคา ≥0/อายุ 1–100 ปี หรือเว้นทั้งสามทั้งหมด; Admin เท่านั้นเข้าถึงการเงิน |
| การบำรุงรักษา | ทรัพย์สิน, วันที่ไม่เกินวันนี้, รายละเอียด | ค่าใช้จ่าย ≥0, ผู้ดำเนินการ, หมายเหตุ Admin; เป็นประวัติเพิ่มใหม่ ไม่มี endpoint แก้/ลบประวัติ |
| รายวิชา | ชื่อ ≤255 | รหัส ≤64 ไม่ซ้ำใน Collegeถ้ามี; backend แก้ข้อมูลได้ แต่เว็บปัจจุบันเน้นเพิ่ม |
| Scenario | รายวิชาของหน่วยงาน, ชื่อ ≤255, active flag | รายละเอียด; ปิด/เปิดการแนะนำผ่านเว็บ; การเลือกรายวิชา/Scenario เป็นตัวเลือกของ Booking ไม่บังคับเลือกตาม preference |
| ชุดอุปกรณ์แนะนำ | เลือกอุปกรณ์ของ Collegeและ quantity integer ≥1 | quantity 0 ใน UI ใช้นำออก; เก็บเป็น recommendation template ไม่ใช่การตัด stock; ยืนยันจำนวนที่แนะนำเหมาะกับ inventory |
| ประเภทหุ่นแนะนำ | เลือกประเภทจากหน่วยงาน | ไม่เลือกทั้งหมดแล้วบันทึกล้างคำแนะนำได้; ผู้จองเลือก asset จริงเอง คำแนะนำไม่บังคับการเลือก |

ผู้รับผิดชอบ/อาคาร/ชั้น/รูปไม่ใช่ required validation ทุกช่อง แต่ควรให้เจ้าของพื้นที่ยืนยันสำหรับ Pilot ไม่ต้องกรอกค่าทดแทนเมื่อยังไม่ทราบ โดยเฉพาะราคาทรัพย์สิน

## สถานะห้องที่ต้องยืนยันกับเจ้าของพื้นที่

- **พร้อมใช้งาน**: แสดงให้จองได้เมื่อ capacity/quantity/exclusive ถูกต้องและช่วงเวลาว่าง
- **ปิดปรับปรุง**: maintenance จองใหม่ไม่ได้
- **ปิดการใช้งาน**: disabled จองใหม่ไม่ได้ เปิดกลับ ready ได้โดย Admin; ข้อมูล/รูป/ประวัติอยู่ครบ
- **รอตรวจสอบ**: pending ของห้อง จองใหม่ไม่ได้ (แยกจาก pending ของคำขอจอง)

ห้อง ID 10 ปัจจุบัน maintenance, capacity 80, ไม่มีผู้รับผิดชอบ/รูป; เก็บสถานะเดิมไว้จนเจ้าของข้อมูลตัดสินใจ ไม่มีการคืนรูปหรือเปิดห้องเอง

## แบบบันทึกสำรวจเปล่า

กรอกชุดนี้ต่อหนึ่งรายการ ไม่ถือเป็นคำสั่ง import และไม่ใส่ข้อมูลสมมติในระบบจริง

## ตรวจหลังกรอก

- Admin reload แล้วเห็นข้อมูลและสถานะตรงรายการสำรวจ
- Staff เห็น operational data ของ Collegeเดียวกัน ไม่มีราคา/ค่าเสื่อม/cost/noteที่จำกัดไว้
- Lecturer เลือกเฉพาะห้อง ready และจำนวนคนไม่เกิน capacity; ปิดปรับปรุง/disabled เลือกไม่ได้
- ทรัพยากรมีประวัติลบไม่ได้ ให้ใช้สถานะปิด/เปิดตามเหตุผลจริง
- ยังไม่มีข้อมูลจริง → คงข้อมูลที่ไม่ทราบว่างและรอการยืนยัน ไม่มีการนำ fixture UAT เข้า MySQL
