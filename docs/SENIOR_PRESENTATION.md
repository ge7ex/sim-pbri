# บทนำเสนอ SIM PBRI V1 — 15 ตุลาคม 2569

**สถานะ: พร้อมให้ Senior ตรวจระบบและให้ข้อเสนอแนะ ยังไม่ใช่การเปิดใช้งานจริงในวิทยาลัย**

## ประเด็นเปิดการนำเสนอ (1 นาที)

SIM PBRI รองรับการจัดการห้อง อุปกรณ์ หุ่นจำลอง รายวิชาและสถานการณ์ การขอจอง การพิจารณา และรายงาน โดยแยกสิทธิ์ตามบทบาทและวิทยาลัย ข้อมูลที่สาธิตทั้งหมดเป็นข้อมูลสมมติในฐานทดสอบแยก

## ลำดับสาธิต (ประมาณ15–20นาที)

| เวลา | บทบาท | สิ่งที่แสดง |
|---|---|---|
| 3นาที | Admin | ห้องและความจุ การปิดใช้งานแยกจากปิดปรับปรุง และเปิดกลับได้ อุปกรณ์ หุ่นจำลอง รายวิชาและScenario |
| 4นาที | Lecturer | เลือกห้อง วันเวลา24ชั่วโมง รายวิชา/Scenario จำนวนคนและผู้ประสานงาน บันทึกร่าง กลับมาแก้และส่งคำขอ |
| 3นาที | Staff | อ่านคำขอ อนุมัติ หรือไม่อนุมัติพร้อมเหตุผล แสดงสถานะกำลังบันทึกและผลลัพธ์ |
| 2นาที | Lecturer | ดูผล/เหตุผล/ประวัติ ยกเลิกคำขอของตน โดยประวัติยังอยู่ |
| 3นาที | Admin/Staff | เปรียบเทียบรายงาน:ข้อมูลการเงินเฉพาะAdmin; Staffไม่เห็น แสดงช่วงไม่มีข้อมูลและหน้าจอมือถือ |
| 2นาที | สรุป | การตรวจสอบ สิ่งที่ยังต้องเตรียมก่อนPilot และรับข้อเสนอแนะ |

ใช้ข้อมูลและช่วงเวลาว่างในdemo เลือกวันอนาคตเพื่อไม่ชนคำขอที่มีอยู่ หลีกเลี่ยงการแสดงไฟล์รหัสผ่านหรือคัดลอกข้อมูลเข้าสไลด์

## หลักฐานที่นำเสนอได้

- Fulltests191รายการ/1707assertions ผ่านสองรูปแบบsession; buildและdependencyadvisory auditsผ่านหลังแก้
- ปัญหาจองพร้อมกันถูกทดสอบให้เกิดจริงก่อนแก้ และทดสอบซ้ำหลังแก้ด้วยฐานMySQLแยก
- Browserทุกบทบาท116หน้า/ขนาดหน้าจอ พร้อมกรณีห้ามเข้าถึงและข้อมูลต่างวิทยาลัย
- Walkthroughจริง13ขั้นและcrossCollege6กรณีผ่าน ไม่มีการเปลี่ยนข้อมูลMySQLจริง
- Securityscanเดิมครบ มีfindingระดับmediumที่แก้และตรวจซ้ำแล้ว ไม่ควรกล่าวว่า“ไม่เคยมีช่องโหว่”หรือ“รับรองความปลอดภัย100%”

## สิ่งที่ขอให้Seniorตรวจ

ความครบถ้วนของขั้นตอนจอง/พิจารณา ความชัดเจนของข้อความและรายงาน ความเหมาะสมของข้อมูลห้อง/อุปกรณ์ และข้อเสนอแนะก่อนทดลองใช้กับข้อมูลจริง บันทึกผลใน `SENIOR_FEEDBACK_LOG.md` โดยไม่ใส่รหัสผ่านหรือข้อมูลส่วนบุคคล

## ก่อนPilot
